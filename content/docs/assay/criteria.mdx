title: "Define criteria"
description: "Choose a comparison kind and declare the exact comparison parameters."
---

Every criterion requires `id`, `kind`, `mode`, `visibility` and `parameters`. Include each required criterion exactly once in the [composition tree](/docs/assay/composition).

## Choose a comparator

| Kind | Observation | Expected value and parameters |
| --- | --- | --- |
| `exact_text` | text | String; exact equality |
| `normalized_text` | text | String; explicit normalization |
| `number_with_tolerance` | number | Number; absolute and relative tolerance; optional unit |
| `number_range` | number | Range; both endpoint flags; optional unit |
| `set_equivalence` | set | Scalar array; item type, order and duplicate policies |
| `boolean_equality` | boolean | Boolean |
| `json_equality` | json | JSON value |
| `observed_execution` | execution | Assertion IDs and reference IDs |
| `manual_evidence` | manual | Review required |
| `qualitative_review` | qualitative review | Review policy ID and version; advisory only |

The first seven are objective comparisons. They accept a literal or a content-bound reference as `parameters.expected`. The remaining kinds report unresolved evidence rather than asserting correctness.

## Text

Exact text compares JavaScript UTF-16 code units, including whitespace and line endings. Choose normalized text when differences in formatting are irrelevant.

Example criterion (a fragment of a definition):

```ts
{
  id: "message",
  kind: "normalized_text",
  mode: "required",
  visibility: "public",
  parameters: {
    expected: { type: "literal", value: "hello world" },
    normalization: {
      lineEndings: "lf",
      case: "fold",
      unicode: "NFC",
      whitespace: "collapse",
      trim: "both",
    },
  },
}
```

Both values undergo the same transformations in this order: line endings, case, Unicode normalization, whitespace, trim. Each choice is explicit. Case folding uses JavaScript lowercase conversion; it does not equate German sharp S with two s characters.

## Numbers

For tolerance comparisons, the allowed difference is the greater of the absolute tolerance and the relative tolerance multiplied by the magnitude of the expected value. The boundary is inclusive.

For example, with expected value 100, absolute tolerance 2 and relative tolerance 0.05, the bound is 5. An observation of 105 passes; 106 fails.


```ts
parameters: {
  expected: { type: "literal", value: 100 },
  tolerance: { absolute: 2, relative: 0.05 },
  unit: "mV",
}
```

For ranges, supply finite `min`, `max`, `minInclusive` and `maxInclusive`. Equal endpoints are valid only when both are inclusive. A numeric observation must use the exact declared unit, or omit it if the criterion has no unit. Assay uses JavaScript numbers and does not coerce strings or convert units.

## Sets

Declare `itemType` as string, number or boolean. The observation uses `items`, not `value`.


```ts
parameters: {
  expected: { type: "literal", value: ["read", "write"] },
  itemType: "string",
  order: "ignore",
  duplicates: "ignore",
}
```

| Order | Duplicates | Comparison |
| --- | --- | --- |
| ignore | ignore | Membership |
| ignore | respect | Multiset counts |
| preserve | ignore | Sequence of first occurrences |
| preserve | respect | Exact sequence |

## Booleans and JSON

Boolean comparisons accept only true or false. JSON equality ignores object key order but preserves array order. Strings and object keys remain exact. Negative zero equals zero. JSON null is a valid expected value.

For the complete parameter and observation contracts, see [record reference](/docs/assay/contracts).
