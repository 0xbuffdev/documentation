There are **two distinct ways to extend Throughline**: (1) author custom computations in your product using the public `tracer()` API, or (2) modify the Throughline package itself to add another `thl <domain>` syntax. Only the first is supported as a normal external consumer in v0.0.2.

## Approach A: make your own computed trace without modifying Throughline

Use an algorithm that calculates values in ordinary TypeScript, but record each meaningful learning step explicitly:

~~~ts
import { compileProgram, tracer } from "@0xbuff/throughline";

function tracePrefixSum(items: number[]) {
  const t = tracer()
    .node("input", "Input", items, { view: "array" })
    .node("sum", "Running total", 0, { view: "number" });

  let total = 0;
  for (let i = 0; i < items.length; i++) {
    const item = items[i];
    total += item;

    t.step(`Add item ${i}`, (s) => {
      s.focus(`input[${i}]`, "sum");
      s.set("sum", total);
      s.note(`${item} contributes to the running total: ${total}.`);
    });
  }

  return compileProgram(t.program());
}

const trace = tracePrefixSum([3, 5, 2]);
// Initial + 3 steps; final running total is 10.
~~~

This approach requires **no private imports** or custom syntax and works with the published package. Your caller is responsible for limiting input size before the loop; the compiler also enforces program and expanded-trace bounds.

### Best practices for computed traces

- Use a stable entity id for the same concept across all steps.
- Declare all nodes and links before recording steps. For dynamic structures, predeclare future entities hidden, and reveal them using step visibility events.
- Use `t.get(target)` between completed steps to inspect current values without mutating the recording.
- Do not use asynchronous step callbacks, nested calls to `t.step`, or attempts to record declarations within steps.
- Prefer one concept per beat: read, calculate, write, or transfer. `send` is not state mutation.
- Test generated frame count, final state, focus and transfer annotations, and error behavior.
- Catch `ProgramError` when inputs exceed the library's limits.

## Approach B: add a new `thl` domain inside the package

In v0.0.2 **there is no public domain-registration API**. Calling `compile("thl search ...")` fails even if your application imports a helper named `search`. Supporting a sixth domain requires a package source change (a fork or a future upstream contribution), not a runtime plugin.

The internal architecture uses this procedure:

1. **Specify a small input grammar**, with explicit parameter rules and work bounds.
2. **Parse** the `ThlBlock` into validated parameters, retaining original source-line numbers.
3. **Build** a version-1 `Program` using `tracer()`, with stable entity and relation identities.
4. **Register** the new domain in the package's internal `DomainName`, `SUPPORTED_DOMAINS`, and computed-domain dispatch map.
5. **Test** both valid and invalid inputs, final snapshots, beat labels, boundaries, and browser readability.
6. **Document** the new syntax, produced steps, examples, and limits; update release notes and compatibility guidance.

These source files and internal registry details are **implementation information**, not stable import surfaces for external packages. Do not deep-import `src/domains/*` or `dist/domains/*` from a consumer.

## Why source-to-trace generation is explicit

Throughline is intentionally not a debugger, dynamic interpreter, or automated algorithm tracer. A computed adapter runs a bounded algorithm written by its developer and records instructional beats. That means an adapter can choose exactly where to pause and which values to emphasize. It also means the adapter author must verify the generated explanation is mathematically correct.

## Test a custom trace generator

~~~ts
import { strict as assert } from "node:assert";
import { compileProgram, tracer } from "@0xbuff/throughline";

const t = tracer().node("n", "N", 0);
t.step("One", (s) => s.set("n", 1));

const trace = compileProgram(t.program());
assert.equal(trace.version, 1);
assert.equal(trace.frames.length, 2);
assert.equal(trace.frames[0].state.entities[0].value, 0);
assert.equal(trace.frames[1].state.entities[0].value, 1);
assert.deepEqual(trace.frames[1].state.changed, ["n"]);
~~~
