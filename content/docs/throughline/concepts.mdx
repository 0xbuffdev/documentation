Throughline separates **what is authored**, **what changes**, and **how it is displayed**. This separation is what makes it useful both in offline build tools and in interactive teaching interfaces.

## Processing pipeline

~~~mermaid
flowchart LR
  A["One thl block"] --> B["Parse domain"]
  B --> C["Program v1"]
  C --> D["Validate & compile"]
  D --> E["Trace v1"]
  E --> F["Inspect or serialize"]
  E --> G["Optional React player"]
~~~

1. **Source:** a single `thl <domain>` block identifies the domain.
2. **Domain parser:** `flow` builds an authored `Program`; other domains compute a `Program` from bounded parameters.
3. **Validation:** invalid identifiers, references, values, operations, and work limits are rejected.
4. **Compilation:** `compileProgram` creates an initial frame plus one complete state snapshot per beat.
5. **Presentation:** host code can read frames directly, or the optional React player can lay them out as SVG and let learners seek without running the source again.

No stage in this pipeline evaluates arbitrary authored JavaScript.

## Entities, relations, and groups

An **entity** is a named state holder with an id, human-readable label, and JSON-like value. Optional properties select a layout lane, value view, and initial visibility.

A **relation** is a directed link between two entity ids. It can have a label and can initially be hidden.

A **group** gives a named lane a layout hint: `row`, `column`, or `tree`. Groups affect presentation, not the meaning of the underlying state.

~~~md
```thl flow
group "Pipeline" as row
node source "Source" in "Pipeline" = "ready"
node target "Destination" in "Pipeline" = null
link deliver source -> target "message"
step "Send"
  send deliver = "ready"
  focus source, target
  note "The message is in transit."
step "Apply"
  set target = "ready"
  note "The destination now holds the value."
```
~~~

Importantly, `send` is a **transfer annotation**, not a state mutation. The destination changes only when a `set` event writes it.

## Beats and events

A **beat** is one named step. Its ordered list of events can:

| Event | Meaning | Persists? |
| --- | --- | --- |
| `set` | Write a value at an entity or valid nested target | Yes |
| `focus` | Mark entities or addressed positions as active | No; frame-local |
| `send` | Annotate a transfer on a relation | No; frame-local |
| `note` | Add explanation to the frame | No; frame-local |
| `show` / `hide` | Change node or link visibility | Yes |

All writes in a beat produce **one resulting snapshot**. Distinct writes to the same or overlapping targets in one beat are rejected; use separate beats when the intermediate state should be visible.

## Frames and snapshots

A compiled `Trace` contains `version: 1`, a `frames` array, and optional scene groups.

Each `Frame` has an `index`, a `label`, the resulting `state`, its source `events`, and optionally a source-line reference. Its `state` includes:

- `entities` and `relations`: the complete current state and visibility flags.
- `active`: focused and written targets for this beat.
- `changed`: target strings written by `set`.
- `transfers`: `send` relations with optional payloads.
- `notes`: captions authored by `note`.

~~~ts
import { compile, describeFrame } from "@0xbuff/throughline";

const trace = compile([
  "thl flow",
  'node status "Status" = "idle"',
  'step "Begin"',
  'set status = "running"',
].join("\n"));

const initial = trace.frames[0]; // "Initial state"
const next = trace.frames[1];

console.log(initial.state.entities[0].value); // "idle"
console.log(next.state.entities[0].value); // "running"
console.log(next.state.changed); // ["status"]
console.log(describeFrame(next, trace.frames.length));
~~~

Snapshots are detached from the input program and built using immutable value updates. Treat returned trace data as **read-only**; mutations to returned objects are not a supported editing API.

## Initial frame and seeking

- Frame zero contains the initial declared values, no active targets, no notes, and no transfers.
- Each following frame corresponds to one authored or computed step.
- `trace.frames[n]` is a direct state lookup. Seeking does not replay earlier steps or rerun the authored source.
- Declared but hidden entities remain in snapshots; they are simply omitted from the visible scene until shown. Hidden endpoints suppress attached visible links.

For a deeper explanation of parsing, validation, scene layout, and replay behavior, see [Architecture and execution model](/docs/throughline/architecture).

## Package version versus trace schema

The npm release here is **v0.0.2**. The `Program` and `Trace` schemas are **version 1**. The independent schema number is not an npm package version and is not a claim that every future package release will preserve all behavior.

For exact TypeScript shapes and entry points, see the [API reference](/docs/throughline/programmatic-api).
